# NAKED BASELINE — ICON TOKEN LAYER CONTRACT

Дата фиксации: 2026-03-12 (Europe/Moscow)

## 1. Цель

Этот документ фиксирует контракт `icon token layer` (`слоя токенов иконок`) для app-owned WPF UI (`собственного WPF UI приложения`).

Задача слоя:

- убрать зависимость UI от россыпи прямых glyph values (`значений глифов`) в XAML;
- подготовить централизованную и дешевую замену текущих baseline glyphs (`baseline-глифов`) на будущие дизайнерские иконки;
- не менять бизнес-логику UI и не внедрять тему на этом этапе.

## 2. Технический формат текущего слоя

На текущем этапе токены зафиксированы как shared string resources (`общие строковые ресурсы`) в:

- `Themes/Baseline.Neutral.Icons.xaml`

Текущая реализация использует semantic icon tokens (`семантические токены иконок`) с glyph-based values (`glyph-значениями`) на базе `Segoe MDL2 Assets`.

Важно:

- consumers (`потребители`) должны зависеть от token keys (`ключей токенов`), а не от raw glyph codes (`сырых кодов глифов`);
- конкретный glyph value (`glyph-значение`) считается временной реализацией токена, а не его смыслом.

## 3. Правила именования

Все токены должны:

- начинаться с префикса `Icon.`;
- называться по смыслу, а не по форме;
- не кодировать в имени конкретный шрифт, набор иконок или Unicode-код.

Допустимые паттерны:

- `Icon.Menu`
- `Icon.Settings`
- `Icon.Folder`
- `Icon.Lock`
- `Icon.Favorite.Empty`
- `Icon.Favorite.Filled`
- `Icon.Copy.Login.Primary`
- `Icon.Copy.Overlay`

Недопустимо:

- `Icon.E8B7`
- `Icon.Mdl2Folder`
- локальные одноразовые ключи под одно окно без семантики.

## 4. Область действия

В token layer должны постепенно входить все app-owned semantic icons (`семантические иконки приложения`) в:

- `MainWindow`
- `EntryWindow`
- `SettingsWindow`, если там есть такие иконки
- shared controls (`общих контролах`) baseline-layer
- app-owned popup/menu surfaces (`popup/menu-поверхностях приложения`)
- app-owned context/info chips (`контекстных/информационных чипах`)

Не входят в этот слой как обязательная часть practical boundary (`практической границы`):

- tray menu (`меню в трее`)
- file/folder dialogs (`файловые/папочные диалоги`) ОС
- другие OS-owned surfaces (`поверхности ОС`)

## 5. Правило для новых изменений

После введения token layer:

- новые app-owned semantic icons должны добавляться через token layer;
- новые прямые `Text="&#x..."` для semantic app-owned icons в окнах больше не считаются нормой;
- временно допустимые прямые glyph values (`glyph-значения`) могут оставаться только там, где миграция еще не пройдена и явно вынесена в следующий подблок.

## 6. Будущая замена на дизайнерские иконки

Текущий контракт специально построен так, чтобы будущая замена шла централизованно:

1. сохраняются semantic token names (`семантические имена токенов`);
2. заменяется источник token values (`значений токенов`) и/или shared icon primitives (`общих примитивов иконок`);
3. массовая ручная правка каждого окна не требуется или сводится к минимуму.

- `Этап 1 / Подблок 1.24` — добить shared control glyphs и провести финальный audit tokenization (`аудит токенизации`) — выполнено
- линия icon tokenization считается подготовительно закрытой
- `Этап 2 / Подблок 2.1` удален из текущего активного маршрута вместе со старой немедленной theme/spec веткой
- временная линия хвостов `Этап 0 / Подблок 0.X` закрыта на подблоках `0.1-0.6`
- следующий допустимый маршрут — только отдельно подтверждаемая новая основная дизайн-ветка
