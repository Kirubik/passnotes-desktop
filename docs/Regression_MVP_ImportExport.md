# MVP Regression: Import / Export (.pnexp)

Этот файл — короткий чеклист (2–5 минут), чтобы быстро проверить, что экспорт/импорт работают и не оставляют «мусор»/частичные данные.

## Export (.pnexp) — базовая проверка
1. Создай тестовую запись и добавь 1–2 вложения (например, `test.docx`, `test.png`).
2. Открой меню **☰ → Export…** и сохрани файл `.pnexp`.
3. Убедись, что:
   - файл `.pnexp` создан и открывается как ZIP (внутри есть `meta.json`, `vault.pnvault`, папка `attachments/` при наличии вложений).
   - рядом с `.pnexp` не осталось временных файлов вида `*.tmp` или `*.bak`.

## Export — проверка ошибок без «мусора»
1. Попробуй экспортировать в папку без прав (например, `C:\Windows\` или другой защищённый каталог).
2. Ожидаемое:
   - приложение НЕ падает
   - появляется toast с ошибкой
   - НЕ создаётся битый/пустой `.pnexp`
   - НЕ остаются `*.tmp` / `*.bak`.

## Import (.pnexp) — базовая проверка
1. Сделай **Export…** текущего хранилища в файл `.pnexp`.
2. Создай в приложении заметное изменение (например, новую тестовую папку/запись) и **Сохрани**.
3. Открой меню **☰ → Import…** и выбери ранее созданный `.pnexp`.
4. Ожидаемое:
   - появляется подтверждение (Yes/No)
   - после импорта данные перезагружены (видно, что «последнее изменение» откатилось к состоянию экспорта)
   - рядом с vault-файлом не остаются `*.tmp`/`*.preimport_*` после успешного импорта

## Import — «всё или ничего» при ошибках
### 1) Неверный файл
1. Возьми любой ZIP/файл и переименуй в `.pnexp`.
2. Попробуй **Import…**.
3. Ожидаемое:
   - toast: «Неверный файл экспорта»
   - текущие данные НЕ меняются.

### 2) Отсутствует blob вложения
1. Сделай экспорт `.pnexp`, где точно есть вложения.
2. Открой `.pnexp` как ZIP и удали один файл из `attachments/`.
3. Попробуй импортировать этот «повреждённый» `.pnexp`.
4. Ожидаемое:
   - toast про отсутствующий файл вложения
   - текущие данные НЕ меняются (не происходит частичной замены).

## Restore from backup — базовая проверка (transaction)
1. Создай бэкап: **☰ → Backup now…**
2. Сделай заметное изменение (создай тестовую папку/запись) и **Сохрани**.
3. Выполни **☰ → Restore from backup…** и выбери созданный бэкап.
4. Ожидаемое:
   - появляется подтверждение (Yes/No)
   - после восстановления данные перезагружены и виден откат к состоянию бэкапа
   - появляется toast об успешном восстановлении

## Restore — защита от неполного бэкапа вложений
1. Создай запись с вложением и сделай **Backup now…**
2. Найди файл бэкапа в папке бэкапов и удали рядом папку `<backup>.attachments` (или один `.pna` внутри неё).
3. Попробуй **Restore from backup…** на этот бэкап.
4. Ожидаемое:
   - toast про отсутствие папки/файла вложения
   - текущее хранилище НЕ меняется.
