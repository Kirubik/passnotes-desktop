## 2) Блок I1 — Хоткеи внутри приложения (ядро)

### I1.1 — Инвентаризация текущих клавиш и точек действий
**Цель:** найти существующие обработчики/биндинги и зафиксировать канонический список хоткеев (по окнам).  
**Окна:** MainWindow / EntryWindow / SettingsWindow / PasswordGeneratorWindow (и при необходимости окна логина/мастер-пароля).  
**Результат:** утверждённый список хоткеев + основа под единый реестр (каталог) для справки.

### I1.2 — Реализация хоткеев (только внутри приложения, без глобальных)
**Цель:** единообразные стандартные действия “как в Windows”, только когда PassNotes в фокусе.  
**Подход:** InputBindings/CommandBindings, вызываем существующую логику (без переписывания сценариев).  
**Набор (ориентир, уточняется по I1.1):**
- MainWindow: Ctrl+F (поиск), Ctrl+N (новая запись при допустимом контексте), Ctrl+E (редактировать), Ctrl+L (Lock), Del (удалить как сейчас), Esc (отмена/снять фокус без сброса правого контекста).
- EntryWindow: Ctrl+S (Save), Esc (Cancel/Close с учётом несохранённых), Ctrl+L (Lock — если уместно по текущей логике).
- SettingsWindow: Ctrl+S (Save если применимо), Esc (Close/Cancel).
- PasswordGeneratorWindow: Esc (Close), опционально Ctrl+C (копирование — только если логика уже есть/безопасна).

### I1.3 — Защита от конфликтов ввода и “случайных” срабатываний
**Цель:** хоткеи не мешают вводу текста, особенно в многострочных полях.  
**Делаем:** guard по фокусу (TextBox/PasswordBox/ComboBox), сохранение поведения Del/Ctrl+A/multi-select/drag&drop.
